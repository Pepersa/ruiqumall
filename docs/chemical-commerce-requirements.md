# 化学品展示与下单网站需求文档

版本：v0.6  
日期：2026-07-03  
参考：震坤行工业品/B2B 采购平台模式、科力普产品分类展示方式，结合化学品展示、企业下单、聚水潭订单导入需求整理。

## 1. 项目背景

公司计划建设一个面向企业客户的化学品产品展示与下单网站。网站用于展示约 200 种化学品产品，产品下包含几千个 SKU，SKU 主要由颜色、包装规格、容量/重量、等级、品牌、批号或其他销售属性区分。

当前参考商品数据文件为 `商品资料_20260620195855_171399319_1.xlsx`。该文件是临时样例数据，用于参考字段结构和 SKU 组织方式，不代表最终商品数据完整度。样例文件包含 5,646 条商品/SKU 行、45 个字段、4,306 个款式编码，商品编码唯一。正式数据会补齐价格和分类，因此网站一期应以 SKU 行为核心导入，再按款式编码、品牌、分类、商品名称等字段聚合成前台产品展示。

当前参考产品分类和属性文件为 `产品目录.xlsx`。该文件包含 `总目录` 分类树，以及按一级/二级分类定义的产品属性模板。不同产品分类共有 SKU、品牌、产品名称、产品型号、产品规格、销售价格等通用属性，同时按类目扩展颜色、包材、克重、箱规、碘值、尺寸、孔径、亚兰值等特殊属性。

本项目第一阶段不做在线支付。客户可在前台浏览商品、加入购物车并提交订单；订单提交后进入后台，由管理员确认价格与库存，并按聚水潭现有导入模板生成订单文件，便于导入聚水潭库存管理系统继续处理库存、发货、出库等流程。

## 2. 项目目标

1. 建立企业级化学品产品展示网站，支持产品分类、搜索、筛选、详情展示。
2. 支持 SKU 级别选型、加入购物车、提交订单。
3. 支持不在线付款的下单模式，订单状态进入公司内部处理流程。
4. 支持生成符合聚水潭导入模板的数据文件；若后续开放 API 授权，也可扩展为聚水潭订单上传接口对接。
5. 支持后台维护产品、SKU、库存展示策略、价格、客户、订单和导出记录。

参考站点：

1. 震坤行：https://www.zkh.com/
2. 科力普：https://www.colipu.com/

参考方向：

本项目不需要在第一阶段照搬大型 MRO 平台的全部功能，应优先实现“展示清楚、选型准确、订单能进入公司内部和聚水潭”的闭环。

## 4. 用户角色

### 4.1 前台客户

企业采购人员、经销商用户或普通访客。

核心能力：

1. 浏览产品和 SKU。
2. 搜索、筛选、查看化学品参数。
3. 加入购物车。
4. 提交订单或询价型订单。
5. 查看订单状态。
6. 维护联系人、收货地址、开票信息。

### 4.2 后台管理员

网站后台一期只设置“管理员”一个角色，不区分运营、商品管理员、系统管理员等多角色。

核心能力：

1. 维护产品分类、产品、SKU、图片、规格、参数。
2. 维护价格、上下架、库存展示规则。
3. 查看客户提交的订单。
4. 修改订单备注、内部备注、确认价格和库存。
5. 生成聚水潭导入文件。
6. 标记导入结果、处理异常。
7. 维护网站基础配置。

## 6. 前台功能需求

### 6.1 首页

首页需要直接让客户进入采购场景，不做纯品牌宣传页。

主要模块：

1. 顶部导航：Logo、搜索框、产品分类、购物车、登录入口。
2. 产品分类入口：按化学品品类、应用场景或品牌分组。
3. 推荐产品/常用产品：展示常采购的产品。
4. 资料入口：SDS/MSDS、COA、TDS、资质说明。
5. 联系方式：在线咨询、电话、邮箱、微信/企业微信入口。

### 6.2 产品分类

产品分类参考 `产品目录.xlsx` 和科力普的分类展示方式，支持三级分类：

1. 一级分类：润滑、油漆涂料、胶粘剂、车间化学品。
2. 二级分类：如车用润滑油、工业润滑油、工业涂料、建筑涂料、灌封材料、建筑胶、干燥剂、活性炭等。
3. 三级分类：如车用齿轮油、车用发动机油、环氧涂料、防水涂料、有机硅灌封胶、瞬干胶、硅胶干燥剂、柱状活性炭等。

分类页需要支持：

1. 分类树。
2. 当前分类下商品数量。
3. 当前分类对应的属性筛选项。
4. 排序。

分类展示要求：

1. 顶部导航提供“全部商品分类”入口。
2. 首页首屏展示一级分类入口，鼠标悬停或点击后展开二级/三级分类。
3. 分类总览页按一级分类分区，每个分区展示二级分类和常用三级分类。
4. 分类列表页左侧展示三级分类树，右侧展示商品列表。
5. 分类筛选项根据类目属性模板动态展示，不同类目展示不同特殊属性。
6. 商品详情页展示当前商品所属的一级、二级、三级分类面包屑。

### 6.3 搜索

搜索对象：

1. 产品名称。
2. SKU 编码。
3. CAS 号。
4. 品牌。
5. 型号。
6. 颜色。
7. 规格/包规。
8. 关键词/别名。

搜索体验：

1. 支持关键词模糊搜索。
2. 支持搜索建议。
3. 支持无结果反馈，可留下需求。
4. 搜索结果可继续按分类、品牌、规格、颜色、包规等筛选。

### 6.4 商品列表

列表字段：

1. 商品图片。
2. 产品名称。
3. 关键规格/参数。
4. 可选 SKU 数量。
5. 起订量。
6. 参考价格或“登录后查看/询价”。
7. 库存状态：有货、需确认、预售、停售。
8. 加入购物车/查看详情按钮。

列表筛选：

1. 分类。
2. 品牌。
3. 通用属性：产品型号、产品规格、销售价格区间。
4. 类目特殊属性：颜色、包材、克重、箱规、碘值、尺寸、孔径、亚兰值等。
5. 库存状态。

### 6.5 商品详情

详情页信息：

1. 产品名称、别名、CAS 号。
2. 产品图片。
3. 产品简介。
4. SKU 选择器：颜色、包规、等级、型号等。
5. SKU 编码、公司内部编码、聚水潭商品编码映射。
6. 价格展示：公开价、登录价、询价或面议。
7. 起订量、步进数量。
8. 库存/交期说明。
9. 通用产品属性：SKU、品牌、产品名称、产品型号、产品规格、销售价格。
10. 类目特殊属性：按所属分类动态展示，例如颜色、包材、克重、箱规、碘值、尺寸、孔径、亚兰值等。
11. 包装与储存条件。
12. 安全与运输说明。
13. 附件下载：SDS/MSDS、COA、TDS、产品说明书。
14. 加入购物车、立即下单/加入询价。

SKU 选择规则：

1. SKU 必须选完整后才能加入购物车。
2. 选择属性后显示对应 SKU 的编码、价格、库存状态、起订量。
3. 缺货或停售 SKU 不允许加入购物车，或进入“询价/联系销售”。

### 6.6 购物车

购物车功能：

1. 展示已选 SKU、产品名称、规格、颜色、包规、数量、价格/待确认价格。
2. 修改数量。
3. 删除商品。
4. 勾选部分商品结算。
5. 按库存状态提示异常。
6. 展示小计、运费待确认、订单总额待确认。

规则：

1. 数量必须满足起订量和销售步进。
2. 不同 SKU 独立为购物车行。
3. 若价格需人工确认，购物车仍可提交，订单金额标记为“待确认”。

### 6.7 提交订单

订单提交信息：

1. 采购企业。
2. 联系人。
3. 手机/电话。
4. 收货地址。
5. 开票信息。
6. 买家留言。
7. 期望交期。
8. 附件上传：采购单、合同、资质文件等，可选。

提交后结果：

1. 生成网站订单号。
2. 订单状态为“待公司确认”。
3. 前台提示：订单已提交，公司将在约定工作时间内确认价格、库存和交期。
4. 不跳转支付，不展示在线支付入口。

## 7. 订单流程

### 7.1 推荐状态流转

1. 待提交：购物车阶段。
2. 待公司确认：客户提交订单后。
3. 待客户确认：公司修改价格/库存/交期后，需要客户确认。
4. 待导入聚水潭：客户确认或公司直接确认后。
5. 已导出/已推送聚水潭：已生成导入文件或 API 上传成功。
6. 聚水潭处理异常：导入失败或字段校验失败。
7. 已受理：公司内部确认订单有效。
8. 已发货：聚水潭或人工回填发货信息后。
9. 已完成。
10. 已取消。

### 7.2 订单审核

后台需要支持：

1. 查看订单明细。
2. 修改订单行价格、数量、备注。
3. 标记库存确认结果。
4. 填写预计发货日期。
5. 追加内部备注。
6. 确认订单可导出。

### 7.3 不付款逻辑

一期订单为“下单不付款”：

1. 网站不接入支付网关。
2. 提交订单即生成订单记录。
3. 订单金额可以为确定金额，也可以为待确认金额。
4. 导入聚水潭时可按未付款/待付款状态处理，具体取决于聚水潭导入模板和公司内部流程。

## 8. 聚水潭导入/对接需求

### 8.1 一期：生成聚水潭导入模板文件

后台订单确认后，系统可生成 Excel/CSV 文件，字段按公司现有聚水潭导入模板配置。

导出要求：

1. 支持单个订单导出。
2. 支持批量订单导出。
3. 支持导出前字段校验。
4. 导出后记录导出批次、导出人、导出时间、订单号、文件名。
5. 已导出的订单再次导出时需要提示，允许重新导出并保留历史。
6. 导出文件字段顺序、表头名称、日期格式、金额格式必须与公司现有模板一致。

建议导出字段：

1. 线上单号/网站订单号。
2. 店铺编码。
3. 订单日期。
4. 买家账号/企业客户编码。
5. 收件人。
6. 手机/电话。
7. 省、市、区、详细地址。
8. 买家留言。
9. 卖家备注/内部备注。
10. 应付金额。
11. 运费。
12. SKU 编码/聚水潭商品编码。
13. 店铺商品编码。
14. 商品名称。
15. 商品属性。
16. 单价。
17. 数量。
18. 明细金额。
19. 明细备注。

必须支持字段映射配置：

1. 网站字段到聚水潭模板字段。
2. 默认值配置，如店铺编码、订单状态。
3. 字段格式转换，如日期、金额、手机号、省市区。
4. 空值校验和异常提示。

### 8.2 二期：聚水潭 API 上传订单

如果后续采用 API，对接方向为网站订单上传至聚水潭自有商城/B2B 店铺。

聚水潭官方订单上传接口约束：

1. 接口：`/open/jushuitan/orders/upload`。
2. 一次最多上传 50 个订单。
3. `shop_status=WAIT_BUYER_PAY` 时不带支付节点；其他状态通常需要支付信息节点。
4. 聚水潭 ERP 内订单状态可从待付款流转到已付款待审核、发货中、打单拣货、已发货。
5. 该接口用于商家自有商城、跨境线下等订单上传场景。

本项目因一期不在线付款，建议优先按 `WAIT_BUYER_PAY` 或公司聚水潭导入模板要求设置订单状态。最终状态值需用公司聚水潭测试环境确认。

### 8.3 聚水潭商品编码映射

商品和 SKU 必须维护聚水潭可识别的编码。

建议字段：

1. `internal_sku_code`：网站内部 SKU 编码。
2. `jst_sku_id`：聚水潭 ERP 内商品编码。
3. `shop_sku_id`：店铺商品编码。
4. `product_name_for_jst`：导入聚水潭时使用的商品名称。
5. `properties_value`：颜色、包规等属性拼接值。

规则：

1. 下单时必须锁定当时的 SKU 编码和商品名称，避免后续改商品资料影响历史订单。
2. 导出前必须校验聚水潭编码不为空。
3. 一对多、多对一映射需要后台显式配置，不允许临时手填。

### 9.3 可直接用于网站的字段

1. `商品编码`：SKU 唯一编码，建议作为网站 SKU 编码和聚水潭商品编码的默认来源。
2. `款式编码`：用于聚合同一产品下的不同 SKU；若一个款式编码对应多行，则前台展示为同一产品下多个规格。
3. `商品名称`：前台商品/SKU 名称。
4. `商品简称`：可作为产品短标题或搜索关键词。
5. `颜色及规格`：可作为 SKU 展示属性。
6. `颜色`：可作为 SKU 属性；但当前数据中该字段经常包含型号和包规，需要后续清洗。
7. `规格`：可作为包规属性。
8. `品牌`：可作为筛选项。
9. `供应商名称`：后台参考字段，一期前台可不展示。
10. `商品状态`：映射为上架/下架状态。
11. `库存同步`：映射为是否参与库存展示或库存同步。
12. `修改时间`、`创建时间`、`创建人`：作为后台审计参考。

### 9.4 正式数据要求

1. 正式商品数据必须包含商品价格，至少需要提供前台展示价或基础售价。
2. 正式商品数据必须包含商品分类，分类应满足前台导航、列表筛选和后台管理需要。
3. `商品编码` 必须唯一且稳定，用于 SKU 唯一识别、下单和聚水潭导出。
4. `款式编码` 应尽量稳定，用于聚合同一产品下的不同 SKU。
5. `品牌` 建议必填，用于前台筛选。
6. `颜色及规格`、`颜色`、`规格` 至少应有一个可用于 SKU 规格展示。
7. `单位` 建议补齐，如瓶、桶、支、箱、个等。
8. `图片` 可分阶段补齐；无图商品使用默认占位图。
9. `国标码`、重量、长宽高、体积等字段可选，一期不作为必填。
10. 临时样例中 `颜色` 字段并非纯颜色，常包含型号、导热系数、包规等；正式数据如能拆分颜色、型号、包规，会显著提升筛选体验。

### 9.5 导入规则

1. 首次导入以 `商品编码` 判断 SKU 唯一性。
2. `款式编码 + 商品名称` 用于产品聚合；如聚合效果不理想，后台允许管理员手动调整产品归属。
3. 若同一 `款式编码` 下有多个 `商品编码`，前台展示为同一商品下多个 SKU。
4. 若 `款式编码` 只有一个 SKU，也允许作为单 SKU 产品展示。
5. 导入时保留原始字段，便于后续重新清洗和映射。
6. 正式导入时价格和分类为必填校验项。
7. 临时测试导入可允许价格或分类为空，但仅用于开发和数据清洗，不作为正式上线数据。

## 10. 产品分类与属性模板

### 10.1 分类树

`总目录` 工作表定义三级分类：

不同类目的产品共同拥有以下核心属性：

4. 产品型号。
5. 产品规格。

不同分类可定义不同特殊属性，前台列表筛选和详情参数根据类目动态展示。

当前 `产品目录.xlsx` 中已出现的属性模板：

### 10.4 属性模板规则

1. 系统需要支持按分类配置属性模板。
2. 属性模板可以绑定到一级分类、二级分类或三级分类。
3. 更具体的分类模板优先级更高：三级分类优先于二级分类，二级分类优先于一级分类。
4. 如果某个分类没有单独模板，则继承上级分类模板。
5. 属性字段需要支持类型配置：文本、数字、价格、枚举、范围。
6. 属性字段需要支持是否必填、是否用于筛选、是否在列表显示、是否在详情显示。
7. SKU、品牌、产品名称、产品规格、销售价格作为通用属性，不应在每个分类重复维护定义。
8. 特殊属性以结构化字段保存，便于后台导入、前台筛选和后续扩展。

### 10.5 前台分类展示参考

分类展示方式参考科力普：

1. 首页顶部提供醒目的“全部商品分类”入口。

4. 分类列表页提供面包屑、左侧分类树、类目属性筛选、品牌筛选、价格筛选和商品列表。
5. 首页可按大类展示推荐商品区，例如润滑、油漆涂料、胶粘剂、车间化学品。
6. 移动端分类页采用一级分类侧边栏 + 二级/三级分类网格。

## 13. Django 技术方案

网站采用 Django 开发。一期应优先利用 Django 自带能力快速完成后台管理、数据模型、表单校验、文件上传和权限控制，减少自研后台成本。

### 13.1 推荐技术栈

1. 后端框架：Django。
2. 后台管理：Django Admin 为主，必要时增加自定义 Admin Action 和自定义管理页面。
3. 数据库：PostgreSQL 优先；开发环境可使用 SQLite。
4. 前台页面：Django Templates + 少量 JavaScript；如后续交互复杂，再考虑前后端分离。
5. 样式：可使用 Bootstrap、Tailwind CSS 或项目统一 UI 方案。
6. Excel 导入导出：使用 Python Excel 库处理 `.xlsx`，导入商品资料，导出聚水潭模板。
7. 文件存储：本地文件系统起步，后续可切换对象存储。
8. 部署：Gunicorn/uWSGI + Nginx，静态文件由 Nginx 提供。

### 13.2 推荐 Django App 拆分

1. `catalog`：产品、分类、分类属性模板、SKU、品牌、商品附件。
2. `cart`：购物车、购物车行。
3. `orders`：订单、订单明细、订单状态、订单备注。
4. `customers`：客户信息、联系人、收货地址。
5. `integrations`：聚水潭导出、字段映射、导出批次。
6. `core`：网站配置、公共枚举、审计日志。

如果一期希望更简单，也可以先合并为 `catalog`、`orders`、`integrations`、`core` 四个 app。

### 13.3 Django Admin 后台要求

1. 管理员通过 Django Admin 登录后台。
2. Product、SKU、Category、CategoryAttribute、Order、OrderItem、Customer、JstExportBatch 等模型注册到 Admin。
3. 商品列表支持按分类、品牌、状态筛选。
4. SKU 列表支持按商品编码、款式编码、品牌、分类、上架状态搜索和筛选。
5. 订单列表支持按状态、创建时间、客户、导出状态筛选。
6. 订单详情页可查看订单明细、客户信息、收货信息、买家留言、内部备注。
7. Admin Action 支持批量导出聚水潭模板。
8. 商品导入可做成 Admin 上传页面或 Django management command。
9. 关键操作写入审计日志。

### 13.4 前台实现要求

1. 使用 Django URL、View、Template 实现首页、分类页、搜索页、详情页、购物车、提交订单、订单详情。
2. 购物车可优先使用数据库保存；未登录用户可使用 session 保存。
3. 订单提交时写入 Order 和 OrderItem，并快照保存 SKU 名称、编码、属性、价格。
4. 前台不接在线支付。
5. 前台价格展示以正式数据中的价格字段为准；如特定商品需要询价，可由 SKU 状态或价格展示策略控制。

### 13.5 导入导出实现要求

1. 商品导入支持读取正式商品 Excel。
2. 导入时校验 `商品编码` 唯一、价格必填、分类必填。
3. 临时样例数据可通过开发导入模式跳过价格和分类必填校验。
4. 导入过程生成导入报告：成功数、失败数、失败行号、失败原因。
5. 产品目录导入支持读取 `产品目录.xlsx` 的 `总目录` 和属性模板工作表。
6. 分类导入时生成三级 Category，并生成 CategoryAttribute 属性模板。
7. 聚水潭导出按公司模板生成 `.xlsx` 文件。
8. 导出前校验订单状态、收货信息、SKU 编码、数量、价格等字段。
9. 每次导出创建 JstExportBatch 记录，并关联订单。

### 13.6 Django 模型设计要求

数据模型以第 12 章为基础实现为 Django Model。

建议：

1. 金额字段使用 `DecimalField`。
2. 数量字段使用 `DecimalField` 或 `PositiveIntegerField`，根据 SKU 销售单位决定。
3. 状态字段使用 `TextChoices`。
4. SKU 特殊属性和原始导入行使用 `JSONField` 保存。
5. 常用筛选字段建立索引，如 `商品编码`、`款式编码`、分类、品牌、订单号、订单状态。
6. 订单明细必须保存快照字段，避免商品资料变更影响历史订单。

## 14. 权限需求

一期权限模型保持简单：

1. 前台客户只能查看自己的订单和提交信息。
2. 后台只有管理员一个角色。
3. 管理员可操作全部后台功能：商品、SKU、订单、客户信息、资料、聚水潭导出、基础配置。
4. 关键操作需记录日志：改价、改数量、导出、取消订单、上下架。
5. 二期如后台人员增加，再扩展多角色权限。

## 15. 化学品特殊合规需求

需根据实际经营品类确认是否涉及危化品、易制毒、易制爆、危险运输、许可经营等要求。

建议一期至少预留：

1. 产品安全资料展示与下载。
2. 限购 SKU 标记。
3. 订单备注中记录客户资质或人工确认结果。
4. 运输方式说明。
5. 危险品提示语。
6. 如需购买资质上传，可先作为订单附件处理，不单独开发复杂审核流。

如涉及强监管化学品，需要在正式开发前由公司法务/合规确认购买、运输、仓储、页面提示和客户资质审核规则。

## 16. 非功能需求

### 16.1 性能

1. 商品列表支持几千 SKU 规模，搜索和筛选响应目标小于 2 秒。
2. 首页和商品详情页首屏加载目标小于 3 秒。
3. 后台批量导出订单支持至少 50 个订单/批次。

### 16.2 可用性

1. 前台适配桌面端和移动端。
2. 后台优先桌面端。
3. 表单字段需要明确校验和错误提示。
4. 购物车和订单提交不得因刷新丢失数据。

### 16.3 安全

1. 登录密码加密存储。
2. 后台接口需要鉴权。
3. 防止越权访问订单。
4. 文件上传限制类型和大小。
5. 防止恶意脚本、SQL 注入、重复提交。
6. 导出的订单文件涉及客户地址和电话，仅管理员可下载。

### 16.4 数据备份

1. 商品、SKU、订单数据需要定期备份。
2. 导出文件建议保存可追溯记录。
3. 订单状态变更需要审计日志。

8. 客户能完成搜索、筛选、查看详情、选择 SKU、加入购物车、提交订单。

10. 后台可确认订单并导出聚水潭导入文件。
11. 导出文件字段、表头、格式与公司现有聚水潭模板一致。
12. 同一订单重复导出有记录、有提示。
13. 客户只能查看自己的订单。
14. 商品上下架、SKU 停售、缺货等状态在前台正确体现。
15. 后台仅管理员登录即可完成全部管理操作，不需要配置角色权限。
16. Django Admin 可完成商品、SKU、分类、类目属性模板、订单、客户信息、聚水潭导出记录的管理。
17. 商品 Excel 导入和聚水潭 Excel 导出可通过 Django Admin 页面或 management command 执行。

## 18. 待确认问题

1. 公司现有聚水潭导入模板的 Excel 表头、必填字段、示例文件。
2. 聚水潭中是否已建立“商家自有商城/B2B/线下店铺”店铺编码。
3. 网站订单导入聚水潭时，订单状态应使用待付款、待审核还是其他内部状态。
4. SKU 编码规则：网站内部 SKU 与聚水潭商品编码是否一一对应。
5. 是否需要展示价格；若展示，一期是否只展示统一价格。
6. 是否涉及危化品或受监管化学品；若涉及，一期采用人工确认还是订单附件上传。
7. 是否需要客户注册后才能看价格/下单。
8. 是否需要销售人员代客下单。
9. 是否需要订单提交后发送短信、邮件或企业微信通知。
10. 是否需要聚水潭发货状态回传到网站。
11. `产品目录.xlsx` 中的三级分类是否就是正式上线分类。
12. 属性模板绑定粒度是否按当前表格执行：润滑、油漆涂料、胶粘剂按一级模板，干燥剂、活性炭、车间化学品其他按二级模板。
13. 正式数据中是否需要把 `颜色` 字段拆分为独立颜色、型号、包规字段。
14. 正式价格字段使用哪一列作为前台展示价：基本售价、市场价、其它价格，还是单独新增价格列。
